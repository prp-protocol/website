PRP L3 — F25-PN

Archived cell evidence · Source revision 4.76

Inventory

The selected column still specifies wire-v4 with protected adjacency and E2E suite 0x0202. The effective wire-v4 document retains ONION and two-flight HS2. The author-approved no-ONION fast-path direction belongs to a separately described successor: the TPA proposal explicitly preserves the existing wire implementation and leaves successor encoding/migration unqualified. These are not interchangeable byte budgets. Rechecking legacy TLV widths for identity suite 0x0002 gives M1=1736 and M2=1778 bytes; two fresh exchanges total 7028 canonical HS2 bytes before framing. For 256 useful bytes split into two 128-byte directions, legacy OPEN/ACCEPT plus four E2E item headers, four RRL record headers and four list counts total 384 inner bytes. The older 640-byte candidate instead contained 512 useful bytes. Neither inner amount is a complete endpoint budget or automatically additive to historical link subtotals. The next source review locates an actual cover scheduler and padding policy: prp_session_cover_work_fn sends an empty two-byte RRL only for active adjacent TX sessions. For suite 0x0202 the unpadded protected unit is 30 bytes (12 nonce + 2 RRL + 16 tag). Its size is raised to the configured padding target, bounded by session capacity. The scheduler uses ceil(8*unit_bytes*10^9/cover_rate_bps) nanoseconds with a 1 ms floor, and schedules from the actual current time rather than replaying missed intervals. At a 256-byte target and 1024 bit/s, one stable TX adjacency sends at most 1+floor(T/2 seconds) automatic cover units over an active interval T. For one such adjacency in each direction and T=60 seconds, the conservative cover-only bound is 18228 native Ethernet byte-times or 19964 over IPv4/UDP/Ethernet. This is a conditional source-derived bound, not measured completion in 60 seconds. Native Ethernet discovery now has a concrete source witness: version 2 SOLICIT and ANNOUNCE payloads are 48 bytes. A received SOLICIT causes a unicast ANNOUNCE when the link is allowed; ANNOUNCE records TX_ADDRESSABLE and RX_OBSERVED with current member generation and lease. One bilateral discovery cycle has two solicitations and two responses, totaling 344 untagged Ethernet byte-times (4*(48+38)). The default scan interval is 10000 ms and advertised lease 30000 ms. On an isolated two-node link, starting with no queued discovery work, no manual solicitations, resets or withdrawals, a 60-second interval has at most 28 such frames under a schedule with spacing at least ten seconds: 2408 byte-times. This accounts for continuing periodic discovery, not just the initial exchange.

Conditions and security scope

Native discovery is source-bound, not an unbounded unknown or a zero-cost assumption. The interval calculation assumes stable allowed attachments, one interface per node, no other discovery participants/traffic and at least 10-second actual scan spacing; a Linux timing realization must preserve that spacing. Local current-member context creation remains necessary after wake; a carrier ANNOUNCE proves no PRP identity and HS2 still authenticates the peer. The 60-second interval is not an execution result or guaranteed delivery time. The complete F25 sequence still needs actual admission, route/relation exchange multiplicity, protected useful-data wrapping and successful delivery time consistent with the positive cover policy from round475. No independent acceptance of integration or the no-ONION successor is inferred. This Ethernet-discovery count is not silently reused for the UDP/IP carrier.

Tor onion service — F25-TO

Archived cell evidence · Source revision 4.37

Inventory

Tor client-operation permits use of a consensus that expired less than 24 hours ago when no live consensus is available. Therefore 24 hours of radio silence does not itself imply that this tolerance has elapsed: a consensus with two hours of validity left at shutdown is only 22 hours past expiry on return. Clients can select microdescriptor consensuses and retain cached descriptors. Separately, directory mirrors support consensus diffs from a known consensus; directory compression includes deflate and recommended LZMA for consensuses and diffs. The size of an uncompressed full consensus is consequently not a mandatory endpoint transfer lower bound for this workload. Four public CollecTor microdescriptor consensuses, valid-after 10:00 UTC on 19–22 October 2026, were downloaded and hashed. Local XZ preset-6 compression of full documents produced 677460–690468 bytes. GNU ed-style differences between consecutive daily documents, compressed with the same setting, produced 62348, 77212 and 79548 bytes. Applying each uncompressed difference reconstructed the next document exactly. Only the first diagnostic difference fits within 65536 bytes, leaving 3188 bytes before any other traffic. Deflate level 9 produced 74814, 91308 and 92984 bytes for the same differences. These are measured document transformations, not a Tor endpoint capture or mirror response. Source inspection of Tor tag tor-0.4.8.16 separates cached-consensus usability from refresh scheduling. networkstatus_consensus_is_bootstrapping returns false for a validated reasonably-live consensus. However, update_consensus_networkstatus_downloads sets the next fetch time to now whenever the consensus is outside its strict validity interval, then checks outstanding requests, retry readiness and missing certificates before requesting a fresh consensus. fetch_networkstatus_callback checks normally every 60 seconds, or every second during the specified testing or bootstrap cases. This interval is not a guaranteed grace period after wake. The reasonably-live predicate in this version includes the exact 24-hour expiry boundary. DisableNetwork delays fetches but also closes outbound connections, so it does not provide directory-only suppression while useful traffic continues.

Conditions and security scope

F25-TO remains Pending. Cache usability does not establish zero refresh traffic. The inspected scheduler does not establish that a complete refresh necessarily finishes before useful delivery either. Do not charge an entire response solely from a scheduled request. The remaining witness must specify retained directory material, loop phase and request state, and count endpoint bytes actually required through delivery, including fresh connections, onion-service lookup and rendezvous. Round436 local GNU-diff compression is not the actual Tor response. This is a version-bounded source trace, not execution of Tor or a statement about every implementation. No criterion or profile change is made.
