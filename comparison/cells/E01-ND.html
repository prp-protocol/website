E01-ND: Yes

Rationale

A public operator report dated 2021-09-26 describes the NDNts video deployment and explicitly identifies producers connected to local NFD over Unix sockets. It reports collected playback observations from July 1 through August 15, 2021, including successful delivery. This is a reported running application/forwarder exchange, not merely a recipe. NDNts implements Interest/Data encoding in TypeScript rather than wrapping the NFD C++ engine; the retained package documentation identifies NDN packet format v0.3. Credit only the common NDN Interest/Data exchange at the application-to-NFD Unix boundary, under the existing E01 bounded-function rule.

Assessment method

Historical operational report with bounded application/forwarder function credit; no new execution

Source context

Public NDNts deployment observations, native packet/Unix transport source and NIST interoperability procedure

Outstanding qualification

The report is by the deployment operator and NDNts author, not an independent rerun. Shared NDN community and contributor involvement are disclosed; separate packet-processing codebases are credited, not institutional non-affiliation. Exact 2021 NDNts/NFD builds are absent, and retained current source identifies implementation lineage, not historical runtime bytes. Applicability to the common packet/Unix interface is a documentary inference, not an execution against selected NFD 24.07. The wider experiment used IPv6 underlay, NLSR, WebSockets and HTTP/3; none replaces the selected direct-Ethernet column or receives credit here. No Ethernet interoperability, selected ECDSA P-256 consumer verification, exact trust policy, independent performance, global scale or complete-profile qualification is established. Separate NIST NFD/NDN-DPDK documentation supplies an Ethernet-unicast procedure and an interoperability statement, but no dated run result was found in that inspected procedure.
