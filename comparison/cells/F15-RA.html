F15-RA: No

Rationale

The missing lower-admission link is now traced. NMinusOneFlowManager installs IPCPFlowAcceptor, which accepts incoming flows once the IPCP is assigned to a DIF; the source explicitly leaves a per-peer flow limit as future work. The default security manager also accepts flows and membership without a quota. The enrollment policy constructs an EnrollerStateMachine before invoking authentication, and the enrollment task stores it by port without an admission cap in that insertion path. AuthSSH2 then allocates context, loads keys, generates DH keys and computes a shared secret before peer proof completes. Claiming a configured peer name reaches work not avoided by the missing-key rejection. No selected early-admission policy bounds that work or the aggregate pending enrollment state. F15 is No for this pinned IRATI composition.

Assessment method

Trace admission registration through state allocation and pre-authentication work; no runtime attack

Source context

Pinned IRATI N-1 flow acceptor, default security policy, enrollment state and AuthSSH2 ordering

Outstanding qualification

This is a source-based assessment of the declared default admission and AuthSSH2 composition, not an exploit, measured exhaustion threshold or universal RINA limitation. Authentication still rejects invalid peers. Per-port duplicate checks and enrollment timeouts supply cleanup but not an aggregate attempt-rate or concurrent-state admission budget; the timer is scheduled after authentication initialization returns IN_PROGRESS. Enrollment retry limits govern local retries, not a cap on arriving requests. Lower-DIF authentication can restrict who reaches an upper boundary, but does not supply the missing bound at the first enrollment boundary. Finite hardware, port space, serialization and ordinary queue capacity alone are not credited as admission protection. A separately selected bounded admission policy could change the verdict. No link-capacity verdict, security certification or runtime claim follows.
