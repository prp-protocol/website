E01-AX: Pending

Rationale

Packet.NET provides a concrete independent-implementation candidate against LinBPQ and XRouter. At pinned commit 1c42ee63, NetRomL4CircuitViaAxudp defines NODES exchange and L4 circuits with application data in both directions against LinBPQ, but explicitly transports AX.25 frames through UDP. NetRomNodesIngestViaNetsim instead receives NODES broadcasts from both peers over a simulated AFSK channel and learns neighbours; its listener never transmits. The interop workflow separates these groups. These are substantially more actionable witnesses than a generic compatibility claim, but test source and workflow configuration alone are not a public successful execution record for the selected direct-radio/serial composition.

Assessment method

Primary-source inspection of test coverage and selected-profile applicability

Source context

Pinned Packet.NET test implementations, workflow and scope notes

Outstanding qualification

Pending: obtain a public result with exact versions showing the selected direct-radio/serial AX.25 plus classic NET/ROM circuit exchange between independently developed stacks, or explicitly qualify which tested subset meets E01. Do not silently replace the carrier with AXUDP or infer L4 circuit coverage from receive-only NODES ingestion. Packet.NET sibling C#/TypeScript/Rust implementations share project provenance and do not independently establish the independence requirement. INP3 is outside the selected classic profile; its documented disabled fixtures and cost-accounting divergence are not failures attributed to classic NET/ROM. No test was run here, no public CI result was verified, and no interoperability failure is inferred.
