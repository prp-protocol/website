E03-RT: Yes

Rationale

LXMF-rs v0.13.0 provides publicly obtainable native Rust Reticulum transport and core implementations under EPL-2.0 with a GPL-2.0-or-later secondary-license option. Source coverage includes raw serial HDLC with secret IFAC, Link identification and recursive path requests dispatched by transport nodes. The library initializes routing/cache state in memory and makes persistence explicit; the selected private tmpfs host policy can also contain configuration/state files. The pinned 1.5.5 delta ledger and exact-tag Link download evidence support a bounded compatibility mapping: the documented remaining gaps concern discovery auto-connect, live virtual-child pacing and Python-specific request-receipt API states, not missing implementation of the selected serial Link composition. The published lockfile contains 247 package records; registry license metadata was obtained for all of them, including reticulum-rs-core, with OSI-approved licensing options throughout. E03 requires an available implementation covering the selected functions, not official reference status or an independently executed interoperability test.

Assessment method

Selected-function source mapping and documentary license coverage

Source context

Pinned LXMF-rs v0.13.0 source, compatibility ledger, repository license and complete published-lockfile license inventory

Outstanding qualification

Documentary implementation-availability decision, not a fresh build, full Python API parity, security audit or raw-HDLC interoperability certificate. The dependency inventory includes optional, development and other-platform packages; it is a conservative lockfile inventory, not a resolved Linux build graph or legal provenance audit. Registry license declarations and repository license text are the licensing evidence. Cargo metadata could not run with the installed older Cargo because the upstream lockfile uses version 4; no successful build is claimed. E01-RT remains Pending: the exact-1.5.5 TCP download and separate KISS/IFAC and identification tests do not establish one executed selected serial profile. The Python reference license is unchanged; this Yes rests on the independent Rust implementation. No LXMF application, IP carrier or local TCP sharing is added to the selected profile.
