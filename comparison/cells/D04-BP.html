D04-BP: Yes

Rationale

Pinned HDTN BPGen and BPSink accept a local endpoint EID through --my-uri-eid and load per-process BPSec configuration. BpSourcePattern places that EID in the primary block, selects its security policy and applies it to outgoing bundles. BpSecPolicyManager reads keys from configured files. Separate ordinary-user processes can select additional local private-ipn identities and hold separate key/configuration files over an already authorized TCPCL/TLS transport without changing host interface addresses, prefixes or routes.

Assessment method

Documentary classification; no new runtime experiment

Source context

Pinned HDTN source retained with SHA-256, 2026-10-15

Outstanding qualification

Local private-ipn endpoint/BPSec identity capability, building on D01-BP's ordinary-user high-port endpoint path. This does not grant globally unique EIDs, automatic routing or peer trust. Use separate user-owned credentials and policies; distributed sample keys are not secret credentials. Pairwise BPSec key holders share authentication authority, so this is not an exclusive asymmetric identity claim. Peer acceptance and transport permission remain separate. No fresh multi-user execution or complete-profile interoperability is claimed. Do not transfer this finding to CGR/SABR or LTP/AOS.
