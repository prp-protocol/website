E03-CJ: Pending

Rationale

Pinned client f5902ac and Rust route server 46c9c1b now have a concrete source-level interface map. SubnodePathfinder sends sq=gr with 16-byte src/tar addresses; service.rs consumes those fields and returns n (destination public key plus big-endian routing label) and np (version encoding), consumed through ReplySerializer. ReachabilityAnnouncer sends sq=ann and signed announcement bytes; the server invokes AnnouncementPacket.check() before parse(), with Ed25519 detached verification of bytes following the 64-byte signature. Both sides construct the state hash by iterated SHA-512 over previous 64-byte hash followed by announcement bytes; the server stores newest first and iterates in reverse. The client checks the returned 64-byte stateHash and resets on mismatch. These are concrete matching interfaces, not just public repository availability. The pinned client and Rust route server use a 20-minute announcement horizon. Both retain the newest announcement, ignore ephemeral link-state entities for redundancy, replace version/encoding entities by type and peers by peer number. The server drops announcements older than the horizon. The client intentionally retains a nonredundant expired announcement, detects the resulting state-hash mismatch, clears its local announcement list and sets the next message reset flag. The server reset branch creates fresh node state. This is an explicit recovery path, not evidence of identical retained lists at every instant or an executed interoperability test. Registry metadata for 413 distinct locked dependency versions was retrieved without fetch errors. Two previously unlocated Git dependency notices were found at their actual filenames: BoringTun LICENSE.md and bendy-cjdns LICENSE-BSD3 contain BSD-3-Clause terms.
