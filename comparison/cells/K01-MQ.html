K01-MQ: Pending

Rationale

The hybrid candidate is now traced beyond a preference constant. Picoquic conditionally registers ptls_openssl_x25519mlkem768. Its pinned Picotls OpenSSL header enables that path for OpenSSL >= 3.5, and openssl.c binds the group to EVP KEM creation/exchange with encapsulation and decapsulation. A separate BoringSSL branch exists. This is executable source-path evidence, not a negotiated-session observation.

Assessment method

Source-path and version-boundary review; no runtime execution

Source context

Pinned picoquic/Picotls source and selected IETF draft

Outstanding qualification

Pin an actual provider/build and require the selected hybrid group at both peers, then verify negotiation and failure behavior when unavailable. Compile-time availability does not establish runtime provider availability or exclude classical fallback. The comparison profile still does not select a TLS group; retain Pending rather than silently changing it. Other builds/providers are not ruled out. No claim of post-quantum certificate authentication or completed cryptographic audit.
