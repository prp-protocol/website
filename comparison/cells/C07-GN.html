C07-GN: Yes

Rationale

CORE can combine multiple small messages for the same adjacent peer into one plaintext buffer before encrypting it. In 0.20.0, the session queue builds that combined buffer and passes it to GSC_KX_encrypt_and_transmit; CORK_ALLOWED optionally delays eligible messages until a bounded deadline to facilitate aggregation. When aggregation occurs, an outside observer sees the aggregate encrypted record rather than separate inner-message boundaries and emission times. This provides a limited batching mechanism under the existing C07 mechanism-presence rule. It is not padding, a constant-rate cover schedule, a randomized anonymity mix or a demonstrated reduction of end-to-end correlation. Total volume, aggregate timing and outer transport metadata remain observable; adjacent peers can decrypt their own CORE traffic. The feature is native CORE behavior, not anonymous file sharing or an added discovery/application protocol.

Assessment method

Versioned CORE documentation and GNUnet 0.20.0 source analysis; no traffic experiment

Source context

CORE message grouping and optional corking; gnunet-service-core_sessions.c

Outstanding qualification

Trace CORK_ALLOWED propagation and ordinary aggregation for CADET traffic in the selected build. Capture separate observed links under sparse and concurrent loads, identify transport fragmentation and aggregate sizes, then compare correlation, latency and overhead with a fixed observer model. Do not assume that corking is enabled by default, that isolated messages are batched, or that an adjacent decrypting relay loses visibility. No traffic capture or effectiveness experiment performed.
