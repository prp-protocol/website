G01-RA: Pending

Rationale

The inter-DIF discovery implementation now has a concrete state inventory. In pinned IRATI, DynamicDIFAllocator stores application-to-DIF entries in app_dif_mappings. enrollment_completed sends all known mappings to a new peer; getAllMappingsForPropagation splits that full inventory into messages of at most 15 objects, not disjoint ownership partitions. register_app stores received mappings and propagates them to other peers. lookup_dif_by_application searches the local map and returns failure when absent: this path does not forward an on-demand lookup to an authoritative partition. The static allocator likewise performs exact application-name lookup; its supporting-DIF prefix comparison is not hierarchical application-name resolution. Therefore extending this replicated discovery service to cover every destination would reproduce a complete global directory at its participants, even if packet forwarding uses small scoped tables. This is a conditional failure of that discovery construction, not proof that all recursive RINA compositions require it.

Assessment method

Exact-map lookup, enrollment snapshot and update-propagation source trace; architecture distinction

Source context

Pinned IRATI DIF allocator and RINA authors' hierarchical layer-discovery proposal

Outstanding qualification

G01-RA remains Pending. The authors' Layer discovery in RINA networks (CAMAD 2012) supplies a different candidate: local directories plus search/neighbor tables, default entries and hierarchical name aggregation. That candidate prevents concluding a universal No from IRATI replication alone. The remaining task is a complete selected-composition inventory for that hierarchical design: application-name search, IDD-peer reachability, inter-provider supporting DIFs and enrollment, showing that no transit/control role requires the full global reachability set. Do not equate a distributed service with partitioned state, message batching with partitioning, or smaller provider forwarding tables with a complete discovery solution. No new IDD policy, executable configuration, global topology or G05 capacity result is adopted in this round.
