G05-MT: No

Rationale

The selected standalone LoRa mesh cannot supply ten billion independently addressable ordinary PKI endpoints in one global routing namespace. NodeNum and packet from/to fields are 32-bit. Both hot NodeDB and the warm key store select one peer key by NodeNum, not by (domain, NodeNum) or full public key. Outbound PKI resolves that key using p->to; a client-supplied different key is rejected, rather than selecting a second peer with the same number. PKI then sets channel to zero, so channel names are not a hierarchical destination namespace. Even granting every 32-bit value, there are only 4,294,967,296 labels, below 10,000,000,000. This is a necessary-condition contradiction for globally addressable endpoints, not a measured maximum node count or a claim that a four-billion-node mesh works. Disjoint local meshes may reuse numbers but do not form the selected globally reachable system; added inter-mesh gateways/translation are not in this profile. Missing benchmarks alone would remain Pending. Here the negative follows from the narrower native addressing/key-selection model, not simply from the absence of a positive scale study. The approved G05 operational limits retain the same ten-billion-device minimum, so the namespace contradiction survives this revision. Distributed state does not enlarge the selected native endpoint namespace. Round171 evaluates an agreed Internet-calibrated regional deployment, not every imaginable construction. All quantitative bounds remain. Regional calibration alone establishes neither capacity nor failure; previous arbitrary star/tree failures do not automatically become No.

Assessment method

Owner-approved regional reference-deployment criterion reconciliation

Source context

Meshtastic NodeNum, destination fields, authoritative key stores and PKI send path

Outstanding qualification

No radio/load experiment was executed. This bound is specific to the selected single native routing namespace and ordinary independently keyed endpoints. Reopen if a concrete native hierarchy or collision-disambiguating destination/key-selection mechanism is added to the selected profile. Local disconnected deployments and application-managed key replacement do not establish that mechanism.
