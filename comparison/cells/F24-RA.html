F24-RA: No

Rationale

The declared RINA composition selects Ethernet and a Wi-Fi mobility mode, but no coordinated sleep service. The pinned IRATI Wi-Fi controller implements scanning, association, network selection and reassociation via wpa_supplicant; those operations do not define receiver listening opportunities or scheduled retention/delivery. The flow and DTCP policies already traced for F27 provide delivery QoS, credit and rate pacing, not a receiver availability schedule. F24 is No for the composition as listed, using the same explicit-binding rule applied to IP and IPv6 IoT/RPL.

Assessment method

Selected-composition assessment; distinguish a carrier family from an explicitly selected sleep service

Source context

Pinned IRATI Wi-Fi control paths, prior flow-policy trace and Linux Wireless documentation

Outstanding qualification

IEEE 802.11 power saving is a concrete possible extension: AP buffering, an association listen interval and beacon TIM/DTIM indications can coordinate radio-off periods and reception. Linux exposes power-save configuration and requires supporting drivers. These mechanisms can carry RINA; they are not disabled or made impossible by its architecture. However, the declared mobility mode does not select that sleep service or identify its configuration. A Yes would require explicitly selecting and qualifying it, just as for F24-RI, rather than inheriting every optional capability of a carrier family. The source review is not a test that every Wi-Fi driver defaults to power save off. No whole-host suspend, lossless retention, energy measurement, runtime failure or universal RINA limitation is claimed.
