C04-PI: Pending

Rationale

The portable session responder supplies concrete proof-before-M2 evidence: process_m1 calls verify_hs2 and remote_identity_matches before preparing the response, and initialization requires a nonempty expected remote identity. This is stronger than an observation-only path. However, initialization accepts only the preferred session suite, resolved in the pinned registry as 0x0202; the selected comparison profiles use 0x0101. The component also does not by itself establish native/UDP ingress behavior or admission CHALLENGE behavior. Keep Pending without silently replacing the suite or equating a portable helper with a complete listener. The checked spec/runtime/kernel HEADs remain unchanged from round119.

Assessment method

Read-only pinned source and profile-boundary analysis; no protocol execution

Source context

PRP runtime portable HS2 responder, wire-v4 suite registry and current spec

Outstanding qualification

Portable runtime process_m1 verifies the HS2 proof and exact expected remote public key before building M2. Its initializer requires PRP_WIRE_V4_SESSION_PREFERRED (0x0202), not the matrix suite 0x0101. This establishes a component barrier, not the selected native/UDP listener path. Bind the selected carrier, peer_context, admission policy and suite to all pre-verification replies; retain the round119 Unix admission fixture distinction and replay/expiry questions. Do not import successor REF-001 admission as wire-v4 listener qualification. Source: round127.html
