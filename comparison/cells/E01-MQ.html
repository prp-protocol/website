E01-MQ: Yes

Rationale

The mp-quic-go public interoperability report states that all 23 tests pass against picoquic commit 01e124ebdf9fc50df307e01e71f2744471ddc470, dated 2026-10-07. The package explicitly targets multipath draft-21 and documents shared draft-20/21 code points. Unlike the earlier draft-06 matrix, the published test source opens and probes explicit path IDs, checks multipath negotiation, transfers a 10 MB response with data on paths 0 and 1, and checks key updates in both client/server role assignments. Credit these common multipath transport functions under E01. The Go implementation is a quic-go-derived fork; its independent counterpart is native C picoquic, not another fork of the same Go engine.

Assessment method

Bounded documentary interoperability witness; no new execution

Source context

Pinned public mp-quic-go/picoquic completed-test report and native test assertions

Outstanding qualification

Implementer-reported result, not an editorial rerun or independent certification. The retained report/source snapshot is 084c13ea; the result pins the picoquic commit but does not separately identify the exact mp-quic-go execution commit or publish inspected per-test qlogs. Tests use real UDP on Linux loopback and HTTP/0.9 hq-interop with a test CA, not selected mutual final-key authentication, proactive duplicate scheduling or physical diverse paths. Setup can skip without Linux/Docker; the completed-test claim comes from the explicit Results section, not from mere test presence or a green generic CI job. Same code points are not full semantic equivalence: credit the inspected path-ID negotiation/data functions only. Preserve reported edge failures involving early connection-ID switching, opening a path too early, initial_max_path_id=0, address-discovery callbacks and compatible version negotiation; the passing cases use documented ordering/configuration workarounds. No full-profile, all-lifecycle, security, E04 performance, or global-scale qualification.
