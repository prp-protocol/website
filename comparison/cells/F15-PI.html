F15-PI: Pending

Rationale

The managed UDP endpoint provider has a shared limit of 256 endpoints. On an allowed carrier link, a nonempty, size-bounded datagram from a new remote tuple matching LISTEN can allocate an ACCEPTED child before PRP wire validation. If the downstream core rejects the unit, the receive function increments drops but does not delete that child. The inspected provider has explicit endpoint deletion and context cleanup; its receive path contains no rejected-child rollback. This exposes a preauthentication allocation boundary outside the bounded HS2 proof tables reviewed in round235.

Assessment method

Static cross-repository ingress, association and allocation trace; no live carrier execution

Source context

Pinned native and UDP carrier implementations inspected 2026-10-15

Outstanding qualification

Add a concrete bounded trial: one managed listener, no other endpoints initially, up to 255 distinct source tuples, invalid small units, then a fresh legitimate tuple. Check actual accepted-child count, controller cleanup, new legitimate admission and existing CONNECT/session continuity. The 255 figure is a source-derived candidate budget (256 shared slots minus one listener), not an executed attack or measured denial. Administrative/controller reclamation and link policy may alter the result. Test live behavior before assigning No; do not claim protected existing sessions fail merely because new endpoint allocation is exhausted.
