F09-MT: Yes

Rationale

The no-next-hop forwarding branch can maintain two live forwarding branches for the same communication. Witness: A reaches CLIENT relays B and C; B and C cannot hear each other, and each reaches D. Both copy the initial packet for forwarding before either hears a duplicate; D can receive through either branch. This is concurrent logical path use over a shared radio medium, not simultaneous physical transmissions, bandwidth aggregation or a source-selected multipath scheduler. Known-next-hop traffic may use only one branch. Architectural inference from forwarding and duplicate-cancellation code.

Assessment method

Read-only code analysis and explicit topology inference

Source context

Pinned Meshtastic firmware: forwarding, authenticated receive and client serialization
