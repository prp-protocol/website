E03-BP: Pending

Rationale

The implementation search now has a concrete convergence-layer boundary. Pinned ION tcpcli.c emits TCPCL version 0x03 in its contact header, so the existing ION BPv7/BSL delivery witnesses do not by themselves implement the selected TCPCLv4/TLS composition. Pinned HDTN has Apache-2.0 public source and a software TCPCLv4/TLS/BPSec path; it is a candidate, not a proven substitute for the exact selected endpoint-security and policy behavior. Its documented default contact routing is Dijkstra over supplied contact plans; the CGR name alone is not evidence of full selected SABR semantics.

Assessment method

Documentary deployment-dependency assessment; no new build or execution

Source context

Pinned NASA HDTN and ION source/build documentation, reviewed 2026-10-15

Outstanding qualification

For HDTN, trace NODE-ID validation, TLS 1.3 selection, selected BPSec primary/payload protection and native admission/authenticated-source delivery semantics against the existing witnesses; reconcile required licenses. Alternatively identify a compatible TCPCLv4/TLS adapter for the pinned ION endpoint without silently using v3 or a weaker policy. For CG also map SABR/BPv7 priority, critical and custody semantics. No complete-profile implementation verdict follows from userspace operation or commodity hardware. Do not infer a universal No from the ION adapter gap.
