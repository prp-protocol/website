D01-MQ: Pending

Rationale

A bounded comparison of picoquic c124cbe975f71b150ea929d325804335d2bdaa34 with multipath-21 confirms matching identifiers for initial_max_path_id, PATH_ACK/ECN, path abandonment/status, path connection IDs, MAX_PATH_ID, blocked notifications and the four path-abandonment error codes. Comments mentioning draft-20 are therefore not an identifier mismatch. A real behavioral difference remains: transport.c emits initial_max_path_id only for positive values and enables multipath only when both endpoints advertise positive values. Draft-21 section 2.1 permits zero to negotiate the extension before allowing additional paths. The project multipath guide explicitly acknowledges this difference and warns against relying on the default multipath-option API. Further source inspection identifies public APIs picoquic_set_preemptive_repeat_policy and picoquic_set_preemptive_repeat_per_cnx. In sender.c, the multipath application-data branch scans pending packet contexts across paths. Eligible unacknowledged frames are copied, retaining STREAM offsets; timing, recent progress and frame-eligibility checks constrain repetition. This is a concrete implementation lead beyond the documentation proposal for a redundancy-specific path API. Stream path affinity chooses one path and is not itself duplication. The pinned candidate was compiled locally in Release mode with picotls f06553b877ada93c860dd1db9002eabf7365292d and picotest a99858e0c33b97b24cd09ceae729f2be33ec01e1. Five existing simulated transport tests passed: satellite_preemptive, satellite_preemptive_fc, multipath_basic, multipath_drop_first and multipath_drop_second. These establish executable evidence for separate repetition and multipath scenarios, not their combination in the selected profile. A local diagnostic variant enabled the existing repeat APIs in four multipath scenarios without changing scheduling. All four passed. Sender and receiver qlogs show stream 4, offset 964662, length 1407 sent on path 0 (packet 396) and repeated on path 1 (packet 389), 11510 simulated microseconds later, before any loss event for the original packet. Both packets reached the receiver; upstream application-length and error checks passed. This supplies a bounded cross-path proactive repetition witness.

Assessment method

Locally instrumented multipath simulation, paired sender/receiver qlogs and upstream application checks

Source context

Pinned picoquic source/guide and multipath-21 sections 2.1 and 6, 2026-10-15

Outstanding qualification

A candidate configuration with positive initial limits on both endpoints avoids the identified zero-limit branch; it is not yet a complete selected-profile witness. Check frame fields, path state, AEAD nonces, mutual authentication, ticket/0-RTT controls and any claimed proactive STREAM duplication. Then trace endpoint socket operations, UID/capabilities, helpers and nonprivileged ports during actual multipath use. No protocol-wide No or conformance certification follows from this bounded candidate finding. For the repeat witness, use a FIN-bearing eligible STREAM range, two validated paths and positive initial path limits; capture the same stream ID/offset on distinct path IDs before loss declaration. Check the scheduler/congestion gates and receiver deduplication. A loop over multiple source packet contexts does not guarantee the output path differs from the original path; no such on-wire result is claimed. The tests ran as UID 0 and used the project simulation harness. They do not demonstrate nonprivileged sockets, real-network operation, distinct-path proactive duplication, selected mutual-authentication settings or full multipath-21 conformance. See round226-runtime.json for reproducible commands and local evidence hashes. The earlier missing combination witness is now supplied in simulation. Live networking, privilege boundaries and full selected-profile authentication/conformance remain unqualified. This experiment is a locally modified test harness with diagnostic instrumentation, not an untouched upstream test or independent implementation.
