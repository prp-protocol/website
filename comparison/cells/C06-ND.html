C06-ND: Yes

Rationale

The selected profile permits unsigned consumer Interests. A consumer can request non-personalized content across independent contexts without a persistent consumer identity field: Name identifies requested content, while the random Nonce identifies an Interest for loop detection. Avoid stable consumer identifiers in names, parameters or optional signatures. NDNLPv2 PIT tokens are hop-local; IncomingFaceId is a local-application indication rather than an end-to-end consumer identity. This credits the consumer role beyond the excluded known access attachment. It does not hide names, request patterns, Ethernet attachment or PIT state, and does not grant producer unlinkability: signed Data may expose a reusable signing identity. A shared upstream forwarder should serve multiple consumers; a uniquely identifying access path is not claimed anonymous.

Assessment method

Bounded consumer-role inference from packet and link specifications; no capture

Source context

NDN packet format v0.3 Interest/Data and NDNLPv2 PIT Token/local-face fields

Outstanding qualification

Use two unsigned consumer contexts behind a shared NFD forwarding path with non-personalized content names and no identity-bearing parameters. Capture beyond the known access attachment, inspect Nonces, LP tokens and local-field handling, and verify both can retrieve validated Data. Audit optional features and traffic/content correlation separately. No capture, automatic context isolation or anonymity certification is claimed.
